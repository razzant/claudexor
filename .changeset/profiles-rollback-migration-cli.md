`claudexor profiles rollback-migration [harness]`, the supported downgrade path of the unified-accounts migration, now runs (#570). The CLI's argument check refused it with a usage error before the command started, so the documented command could not be used. `claudexor help` and the profiles usage now list it. Omitting the harness reverses every migrated harness. An explicitly empty or blank harness, such as an unset `"$HARNESS"`, is refused before the daemon is contacted, as are a second operand and `--harness` in place of the operand. When a harness's runs are blocked by an incomplete migration or an interrupted rollback, the run refusal (and, for an interrupted rollback, the daemon startup log) now names `claudexor profiles rollback-migration <harness>` for that harness instead of the nonexistent `claudexor accounts-migration-rollback`. An externally owned daemon refuses `claudexor daemon stop`, so for an incomplete migration the refusal's restart advice now covers both lifecycle owners: that command for a standalone daemon, and the owning application for an externally owned one. Rollback now ignores inherited object-property names that are not actual migration records, avoiding a corrupt migration entry; rollback of real named records and the all-record form retain their existing semantics.

**Behavior change:** `--display-name` now works only with `profiles add`. `claudexor profiles` with or without `list`, and its `login`, `enable`, `disable`, `remove` and `rm` verbs, used to accept and ignore the flag; they now refuse it with exit 2 before contacting the daemon. `rollback-migration` refuses it too, so the flag cannot consume the intended harness and leave an all-harness rollback. Remove the flag from any script that passes it to those verbs.
