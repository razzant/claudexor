A result delivered into a shallow clone (`git clone --depth …`) is now verified like one delivered into a full clone (#501). The fresh verify clone reads the target's objects through `git clone --shared`, which Git silently ignores for a shallow source. A shallow target that was dirty, or whose HEAD had moved since the run, was therefore refused: apply failed with `isolated clone checkout failed: … unable to read tree`, or reported the missing composed tree as a result that does not apply, and a commit onto a dirty shallow target showed that clone error in place of its usual dirty-tree refusal. Claudexor now lists the target's object directory itself when Git did not, for a run's isolated envelope as well, so these deliveries verify, run their gates and then apply, commit or refuse as on a full clone. Nothing else about delivery changes; no network access or object copy is added. A linked worktree of a shallow repository, which Git copies locally without its shallow boundary, now gives a copy carrying that repository's own boundary, so `git log`, blame or `fsck` in a run's envelope or a delivery's verify clone stop at the boundary instead of failing on missing parents.
