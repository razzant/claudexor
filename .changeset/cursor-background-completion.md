A Cursor command handed to a background shell no longer reads as running forever. The handoff now says "Handed off to background; completion not observed" (after its timeout when the 30-second shell timeout moved it) instead of "still running". When Cursor later reports, in a `system/task_notification` frame, that this shell ended with `success`, `error` or `aborted`, Claudexor updates the same command instead of dropping the frame as unrecognized: a `status` event with `payload.code: command_outcome_refined` names the original tool call and carries the refined `command_outcome` (`completion_reported` with that word, the handoff facts kept), and the complete native frame is kept as evidence. The exit code stays unknown, because the frame has no typed one and free-text detail is not parsed, so the command reads "Completion reported; exit code unknown" or "Completion reported (error); exit code unknown". It is never shown as a success, a passing test or a recovery from an earlier failure. The run's telemetry keeps each report as a command fact (`reported_command_outcomes`) that `claudexor inspect` lists apart from tool errors: the tool call itself stays `ok`, and a reported `error` or `aborted` is no tool warning, failed attempt or ranking penalty, since a deliberately stopped dev server may simply have finished correctly. The macOS transcript updates that command's row in place (found by its exact tool-use id, never by name, and never to green), the run timeline shows the update as a warning row, and the continuation packet carries the refined outcome. ACP sends one more `tool_call_update` for the already closed call with its new text and `_meta`, leaving `status` out so the terminal `failed` stands. `claudexor acp serve` now actually streams tool activity: its run event feed, which carried only timer notices, also delivers each tool call, its result and these refinements (never narration or thinking), and each ACP call id names the run and try that issued it, so tries or turns that reuse a native id stay separate calls. The macOS transcript pairs a result only with its own try's call of the same tool-use id; a result whose call never arrived gets its own row instead of closing another open command, and an id-less result closes only the one open id-less call of its exact name in its try when the name fits the existing tool-field limit; longer names remain separate rows. `claudexor inspect` says how many reported outcomes it shows of the total. A notification that names no pending handoff of the same session (an unknown or progress id, a duplicate, a shell id shared by two pending handoffs) or carries any other status changes nothing and stays counted as an unrecognized frame. The frame shape follows one native cursor-agent 2026.08.11 run and that build's stream writer; no sanitized recording exists yet (razzant/claudexor#546).
