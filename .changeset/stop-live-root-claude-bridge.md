Run preparation no longer creates a `CLAUDE.md` in a durable project root
(CONCEPT-CHANGE INV-113). Before, a write run, including a convergence attempt, on
a project with `AGENTS.md` and no `CLAUDE.md` wrote a thin `@AGENTS.md` bridge
there, and wrote it again after the user deleted it. The compatibility bridge
is now created only inside a disposable Git envelope. A `CLAUDE.md` already in
the project, including one an earlier version generated, is never removed or
rewritten, and new runs emit no `project.claude_bridge.created` event.

Patch capture still keeps a pristine envelope bridge out of the result only when
Claudexor created it in that envelope and its bytes still equal what that
envelope's writer emitted. The persisted created-this-run marker now records which
generated bytes were written; a marker from before this change means the earlier
bytes. A candidate that edits the bridge, including a rewrite to the other
version's exact bytes, is captured as real work.

A historical `project.claude_bridge.created` event still replays, and the CLI now
labels it as a file creation whose reading is not confirmed. Documentation no
longer promises that every route reads the same instructions or that deleting the
generated file stops bridging.
