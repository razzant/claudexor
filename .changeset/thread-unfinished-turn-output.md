A thread turn that ended without a final answer no longer reaches the next lane as an empty answer (#405). When a later turn runs on another harness or account, the continuation packet (`context/THREAD.md`) and the summary pass now carry what that turn said, under a heading that the text is not a completion verdict. The text is read by the rule a `continueFrom` successor already used: the run's `final/retained-output.md` exactly as stored, else the same projection of its `events.jsonl` when the run's terminal never wrote that file, as after an engine restart. The heading says the turn ended without a final answer when its run did not succeed; when the run's terminal facts cannot be read it says only that no final answer is recorded and the outcome is unknown. Successful plan and report turns, which write no `answer.md`, keep their earlier rendering, and a failed or capped Plan turn is carried like an Ask turn. Within the per-turn 4 KiB output budget an unfinished turn keeps the end of its output, where its newest text is, so the retained file's fixed preamble no longer fills the allowance; the summary pass's 2 KiB and a collapsed one-line entry's 200 characters keep the end the same way. Wherever `THREAD.md` cuts a turn's verbatim output, an answer's included, the cut mark names the file that holds the whole output. Limits: an answered turn's one-line entry names no file, and no file is named for the turns a cached summary replaces; a summary cached before this change is reused until the thread's collapse boundary moves; an earlier turn without the retained file has its event log read each time a packet is built.
