The daemon's credential invalidation also drops the cached Claude model picker (#572). After a setup-job login, a profile created, toggled or removed, or a secret set, the next model listing that reads a profile's catalog probes it again, where it could previously answer with the earlier account's rows from the hour-long cache; a profile whose secret is missing, as after a delete, answers the hint rows without probing. The drop runs before the configuration and quota reads that can fail. A probe that started before the change still neither stores its answer nor displaces a newer probe. The same invalidation runs on every settings save, whatever it changed, and drops every scope including the credential-free binary one, so the next read of each scope spawns one prompt-free `initialize` probe again. The cache belongs to the daemon process and nothing re-reads it on a schedule: after a change the daemon does not observe, such as the CLI's direct Claude profile login or a vendor logout, `models()` keeps the earlier rows until its first call past the hour, an observed invalidation, a changed binary or a daemon restart, and no daemon models API offers a fresh picker read. The account view (`?view=accounts`) retains its own copy past that hour until an observed invalidation, harness maintenance, an Accounts refresh or a restart discards it, and a refresh inside the hour retains the adapter's cached rows again.
