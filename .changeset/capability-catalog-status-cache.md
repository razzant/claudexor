`GET /v2/agent-capabilities` (and the MCP `claudexor_capabilities` tool, which reads it) now uses the daemon's existing status-projection cache, the same one default `GET /v2/harnesses` reads use. Concurrent and in-window reads share one harness sweep, so normally one sweep runs at a time, about one per 15 seconds (a config change or invalidation during a sweep starts a fresh one beside it, and only the fresh one's result is cached; a reader that had already joined the older sweep still receives that one's result); the first read after the window still waits for a full sweep. A computed catalog is served for 15 seconds (its `generatedAt` says when it was built), on top of the doctor's own reuse of a report (by default 90 seconds when OK, 15 seconds otherwise), so an out-of-band change such as a vendor CLI login outside the daemon can take about 30 seconds (non-OK to OK) or 105 seconds (OK to broken) to show, plus sweep time. A change to the global config recomputes it at once, and the daemon's credential mutations and setup logins invalidate it. Callers that read the catalog for one static fact, such as a harness row's `liveInput`, no longer pile up concurrent discovery, doctor and model-inventory sweeps or leave several running after they give up. `claudexor capabilities` still composes the catalog in-process.
